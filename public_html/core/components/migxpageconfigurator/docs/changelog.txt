2.4.0-dev (в разработке)
==============
Крупный релиз: расширение address-space (`rfield`/`tv`/уровни), edit-mode рендер и публичный API под визуальный фронт-редактор **mpcVisualEditor**. Ведётся поэтапно (M0–M9); записи добавляются по мере готовности этапов. Версия в разработке — НЕ ставить в прод до перехода на `-rc`.

- **[M0] Билдер под два пакета.** `_build/build.php` параметризован: `php build.php` собирает mpc (как раньше, backward-compatible), `php build.php mpcvisualeditor` — пакет mpcVE из `_build/mpcvisualeditor/config.inc.php`. Оба транспорт-пакета собираются с одного dev-сайта. Проверено боевой сборкой обоих на тестовом сайте.
- **[M1] Address-space: `data-mpc-rfield` + `data-mpc-tv` (сторона Cutter).** Новый top-level пас `Cutter::handleResourceFields()` (по образцу `handleInformation`): `data-mpc-rfield="pagetitle"` → `{$resource.pagetitle}`, `data-mpc-tv="myTV"` → `{$resource.tvs.myTV}`. Render.php прокидывает в скоуп секции `$resource` — полный массив полей ресурса с подмассивом `tvs` (`Render::parseConfig`). Поддержаны: `href` (a/link), `src` (img/source), `innerHtml`/`data-mpc-unwrap`, обёртка `data-mpc-if`. rfield/tv **не лексиконятся** (значения per-resource, не общие между страницами) и предназначены для динамических, не `data-mpc-static`, секций. Грабер resource-поля в `mpc_config` **не пишет** (render+edit-only; запись значений — через будущий фасад `writeField`, M4). Маркеры `rfield|tv` добавлены в strip-паттерн. Тест `testCutterTransformsResourceFieldsAndTVs` (+1, всего 138, все зелёные).

- **[M4] Публичный write-API (частично).** `MpcServices\Handlers\FieldWriter::write($address, $value)` — единая точка записи значения по адресу (для mpcVisualEditor и внешних вызовов). Реализованы `type=rfield` (нативная колонка ресурса из белого списка `mpc_editable_resource_fields`: pagetitle/longtitle/description/introtext/content/menutitle) и `type=tv` (значение TV); после успешной записи — событие `mpcOnFieldSave` + инвалидация resource-кэша контекста. `type=field` (mpc_config) — пока заглушка (нужна иерархия уровней M2 + согласованная работа с lexicon, делаем с проверкой на сайте). mpcVE-фасад `Mpcve::writeField` делегирует сюда через общий vendor mpc. Стаб `ModxObjectStub` получил `setTVValue`. Тесты `FieldWriterTest` (+7, всего 145, все зелёные).

- **[M2 + M4-config] Уровни (local/template/global) + запись config-полей.** `MpcServices\Handlers\ConfigFieldWriter` — чистая мутация значения внутри JSON `mpc_config`: top-level поля и migx-строки (`parentField[idx].field`); поиск секции по `section_name`/`MIGX_formname`; полностью юнит-тестируемо (+7 тестов). `FieldWriter::writeConfigField` теперь пишет `type=field` с резолвом уровня: **local** — TV `mpc_config` самого ресурса; **template** — донор (ребёнок staticBlocksPage с тем же шаблоном, как в Render); **global** — staticBlocksPage (`mpc_static_block_page_id`). Лексиконные поля (адрес `lexiconized=true`) пока НЕ пишутся в config (там лежит ключ; запись текста в lexicon-файл — отдельным шагом, с проверкой на сайте), чтобы не затереть ключ. Инвалидация на template/global шире resource-cache одного контекста — помечено «проверить». Тесты `ConfigFieldWriterTest`/`FieldWriterTest` (+9, всего 154, все зелёные).

- **[M-types, фундамент] Кастомные resource-классы `mpcType` / `mpcTypeCollection`** (по образцу minishop2 msProduct/msCategory). Замысел: служебные данные типа страницы (`type_name` ← бывш. pagetitle, `file_name` ← бывш. introtext) хранить ОТДЕЛЬНО от контента ресурса (таблица `mpc_type`, объект `mpcTypeData`, 1:1 по id), чтобы потом безопасно перезаписывать поля ресурса. `mpcType` наследует `modResource` и маршрутизирует поля по `_originalFieldMeta` (нативные → parent, остальные → `Data`), ленивый `loadData()`, сохранение Data каскадом через composite на `parent::save()`, `load/loadCollection` c `addDerivativeCriteria`. `mpcTypeCollection` — контейнер (composite OwnTypes по parent). Классы объявлены в схеме (`class_key` default + composite `Data`) для попадания в metadata-карту; генератор root-классы не перезатирает. **Полный цикл проверен на тестовом сайте:** create mpcType → save (id, class mpcType_mysql) → reload через `getObject('modResource')` приходит mpcType с проксированными type_name/file_name → строка в `mpc_type` есть → `remove()` каскадно удаляет Data. Иерархия (подтверждена): **resource > type > collection** по приоритету при рендере; связь ресурс→type по шаблону (как donor в Render), type→collection по parent. **Миграция `console/migrate_types.php`** (dry-run по умолчанию, `--apply`): `staticBlocksPage`→mpcTypeCollection, его дети→mpcType (+ pagetitle→type_name, introtext→file_name; pagetitle/introtext не очищаются — обратимо). Проверено на тестовом сайте: 7 ресурсов мигрированы, идемпотентно, поля читаются из mpc_type. **Render: явное разделение type/resource.** `donor + config` переименовано в `type + resource` (behavior-preserving): добавлен хелпер `getTypeResource($template)` (mpcType-донор по шаблону под коллекцией), переменные `donorConfig/config` → `typeConfig/resourceConfig`, merge с явным комментарием приоритета **resource > type** (без отдельного collection-фоллбэка — не нужен). Тот же хелпер в `copyConfig`. Внутренний ключ TV `donor_` оставлен (функциональный контракт). Проверено на сайте: страница #1 рендерится (`render->handle = true`) после миграции типов. Дальше (в работе): CRC read-only форма, регистрация class_key в дереве, грабер пишет служебку в type_name/file_name, безопасный overwrite полей ресурса (кроме `alias`/`uri`/`template`) + грабер-сторона rfield/tv.

2.3.16-rc
==============
- Обработка атрибута `title` для медиа (`img`, `picture`, `video`, `audio`). `title` — человекочитаемый текст (тултип/доступность), поэтому лексиконится как `text` с суффиксом поля `_title` — симметрично `alt`, на обеих сторонах (грабер пишет ключ, каттер навешивает `| lexicon`).
- Грабер `FieldValueExtractor`: `getImageValue()` добавляет `title` в извлекаемые атрибуты — покрывает и standalone `<img>`, и `<img>` внутри `<picture>` (туда зовётся тот же метод через `getPictureValue`). `getMediaValue()` добавляет `'title' => 'string'` для `<video>`/`<audio>`. Лексикон-опции для `title` строятся **локальной копией** `$options` (`fieldName = <base>_title`), чтобы не задеть scope `src`/`alt`/`poster`/`sources`, использующих общий `$options`. Заодно `alt` в `getImageValue` переписан на захваченный до цикла `$baseFieldName` (поведение идентично, но устойчиво к порядку атрибутов).
- Каттер `PlaceholderProcessor`: `setImgPlaceholder()` — `title` в `$attrSpec` (`text`, `_title`); `setMediaPlaceholder()` — `title` в `$mainLexiconAttrs` (`video`/`audio`) и в `$imgLexAttrs` (внутренний `<img>` у `picture`); `setAttributes()` — `'title'` добавлен в `$allowedAttrs`, иначе плейсхолдер не эмитится. Решение `shouldLexiconize('text', <field>_title, parent)` совпадает на обеих сторонах → ключ грабера и `| lexicon` каттера согласованы.
- Границы (как у существующего `alt`): сам элемент `<picture>` и `<source>` `title`-ом не граблятся (там `title` нестандартен) — у `picture` работает `title` на внутреннем `<img>`. Поле формы `title` в гриде менеджера — генерируемый из БД артефакт (`migx_configs.json`), кодом не правится.
- Исключение через `exclude_lexicons.inc.php`: `*_alt` безопасен (на `_alt` обычно ничего другого не оканчивается). `*_title` **зацепит и обычные текстовые поля** `title` во вложенных списках (у них `fullPath = <родитель>_title`) — для `title` исключайте точечно (`clip_title`, `image_title`).
- Тесты: +6 (`ContentParser`: извлечение `title` из `img` и `video`; `PlaceholderProcessor`: лексикон/не-лексикон `title` для `img`, `video`, `audio`). Всего 137, все зелёные. Обновлён эталон `grabber/about_fields.json` — у `<img>` без `title` теперь ключ `"title":null` (как и любой отсутствующий атрибут в `getImageValue`). Версия пакета `2.3.15 → 2.3.16`.

2.3.15-rc
==============
- Cutter `lex()`/`getThumb()`/`setAttributes()`: лексикон-теги внутри **статичной секции** (`data-mpc-static=1`) **внутри foreach** рендерились как `##'{$item1.content}' | lexicon}`. В статике обёртывающий `##foreach}` отложен (firstSymbol=`##`), поэтому на eager-пассе loop-переменная `$item1` ещё не в скоупе → внутренний `{$item1.content}` (одинарная `{`) интерполировался мимо скоупа → `{'' | lexicon}` в `parsed/` (пусто на сайте). Для нестатичных секций `{foreach}` исполняется на eager-пассе, `$item1` в скоупе — там eager-интерполяция нужна (значение запекается, пока loop-переменная жива). Теперь для `isStatic && level > 0` переменная откладывается целиком: `##$item1.content | lexicon}` → после `##→{` → `{$item1.content | lexicon}`, резолвится когда отложенный foreach реально итерирует.
- Решение вынесено в общий хелпер `deferLexiconVar($properties)` (`isStatic && level > 0`) и прокинуто во все field-методы (текст, картинки, медиа, source-атрибуты) через новый параметр `$deferVar` у `lex()`/`getThumb()`/`setAttributes()`. Top-level статичные поля (level 0) сохраняют eager-интерполяцию `##'{$title}' | lexicon}` — там `$title` в скоупе.
- Тесты: +3 (`testSetPlaceholdersStaticForeachDefersLexiconVar`, `testSetPlaceholdersStaticTopLevelKeepsEagerInterpolation`, `testGetThumbDeferVarInStaticForeachLeavesInputAndSizesBare`). Всего 131, все зелёные.
- Прочее (без изменения логики): нормализация выравнивания `=>`/`=` к одиночному пробелу в `SectionFileWriter`/`ContentParser`/`FieldValueExtractor`/`SectionProcessor`; docstring + trailing comma в дефолтном `exclude_lexicons.inc.php`; опечатка «Именя»→«Имена» в `examples/fields.json`.

2.3.10-rc
==============
- Cutter теперь учитывает `excludeLexiconFields` при расстановке `| lexicon` (баг 2.3.9-rc). Раньше `PlaceholderProcessor::isLexiconField()` проверял только `useLexicons` + `translatableContentTypes` и эмитил `##'{$expr}' | lexicon}` даже для полей, которые грабер пропускает по exclusion-паттерну → переопределённый `lexicon`-модификатор возвращал пусто → пустота в выхлопе.
  - В `LexiconManager` добавлен публичный метод `shouldLexiconize($contentType, $fieldName, $parentFieldName = '')` — комбинирует `isLexiconField` (content-type translatable) + `isFieldExcluded` для `fieldName` и `parentFieldName`. Это единый источник решения для грабера и каттера.
  - `isFieldExcluded` защищён от отсутствующего/невалидного `excludeLexiconFields` (раньше падал warning'ом).
  - `PlaceholderProcessor` получает `LexiconManager` через DI вместо дублирующего `isLexiconField`-хелпера. Удалена локальная копия логики.
  - `lex()` принимает `fieldName` и `parentFieldName`, делегирует в `shouldLexiconize` через приватный `shouldLexiconize`-обёртку. Каждый field-метод (`setDefault/setImg/setBackground/setMediaPlaceholder`) передаёт контекст.
  - `setAttributes()` теперь принимает `array $lexiconAttrs` (attrName → bool) вместо `attrName → contentType`. Caller сам вычисляет решение через `shouldLexiconize` с правильным контекстом (fieldName, accumulated parent). Это нужно потому что `setAttributes` обрабатывает разные атрибуты с разной семантикой fieldName (например, `alt` грабер пишет с суффиксом `_alt`).
  - `setPlaceholders` при рекурсии в items накапливает `parentFieldName` (`prevParent + '_' + fieldName`) — раньше перезаписывал. Это нужно для корректного матча exclusion-паттернов на накопленный путь (типа `compare_list_compare_product`).
  - **Known limitation**: cutter работает на уровне схемы и не знает row-индексы. Exclusion-паттерны с конкретными idx (`cards_1_subtitle_2`) на cutter-стороне **не сматчатся**. Для row-агностических исключений используйте glob (`cards_*_subtitle_*`). Grabber по-прежнему обрабатывает оба варианта корректно. Поведение задокументировано в docstring `LexiconManager::shouldLexiconize`.
  - Тесты: добавлено 4 теста на `shouldLexiconize` в `LexiconManagerTest` (exclude по fieldName, parentFieldName, glob, defensive default). Добавлено 3 теста в `PlaceholderProcessorTest` (exclude по точному имени, по glob, по parent при вложенной структуре). Всего 121 тест, все зелёные.

2.3.9-rc
==============
- Переработана работа с лексиконами: вместо хранения Fenom-тега `{'key' | lexicon}` как значения поля теперь в БД лежит голый ключ, а Cutter при генерации tpl сам строит выражение с модификатором `| lexicon` для тех полей, чей content-type есть в `translatableContentTypes`. Это закрывает баг с кавычками внутри `mpcThumb` (значение перестало быть Fenom-кодом — нет конфликта с обрамляющими литералами) и убирает костыли `isLoopVar` / `isLoopVarInStaticCtx` / `{if}`-страховки из `getThumb()`.
  - `LexiconManager::setLexicons()` возвращает ключ вместо Fenom-тега; запись `key → sanitized value` в lexicon-файл сохраняется как было.
  - `LexiconManager::isLexiconField($contentType)` — публичный хелпер, единый для Cutter и Grabber: `useLexicons && in_array($type, translatableContentTypes)`.
  - `PlaceholderProcessor::lex()` — приватный хелпер. Для нелексиконных полей эмитит `{$expr}` (как раньше). Для лексиконных — `##'{$expr}' | lexicon}`: pdoTools-интерполяция `'{$expr}'` на eager-пассе подменяет ключ литералом, `##→{` оставляет нормальный Fenom-тег `{'key' | lexicon}` для final-пасса, где лексиконы уже загружены. Без отложенного `##` лексикон-модификатор на eager-пассе возвращает пусто (переопределённый отдаёт `''` для отсутствующих ключей, файл ресурса ещё не подгружен).
  - В каждом field-методе (`setDefaultPlaceholder`, `setImgPlaceholder`, `setBackgroundPlaceholder`, `setMediaPlaceholder`) теперь идёт через `lex()` с правильным content-type: текст — `text`, картинка — `image`, video/audio src — соответствующий тег, poster — `poster`. width/height/controls/loop и прочие булевы/числовые атрибуты не локализуются.
  - `PlaceholderProcessor::getThumb()`: параметр `useLexicon: bool`. Если true — сниппет-вызов откладывается через `firstSymbol = '##'`, `input` оборачивается в `('{$expr}' | lexicon)`, а размеры баковатся через `{$item.width}` (для нестатичных секций `$item` не в скоупе final-пасса). Уходит детект `isLoopVar`/`isLoopVarInStaticCtx` и страховочный `{if}` — теперь caller сам решает по `isLexiconField()`.
  - `PlaceholderProcessor::setAttributes()`: новый параметр `array $lexiconMap = []` — маппинг `attrName → contentType`. Атрибуты, отсутствующие в карте, всегда выводятся без `| lexicon`. Обратная совместимость сохранена (default — пустой массив).
  - Тесты: `LexiconManagerTest` обновлён под новый return-value, добавлены 4 теста на `isLexiconField`. `PlaceholderProcessorTest` — 9 новых тестов на лексиконные сценарии (text/image/alt/video/audio/poster/bg/thumb с лексиконом и без), плюс `testGetThumbWithUseLexiconDefersAndWrapsInput` и `testGetThumbWithUseLexiconBakesWidthHeightAsLiteral`. Всего 113 тестов, все зелёные.
  - **Миграция**: после установки запустить `mgr_tpl` для регенерации tpl-файлов и значений в БД. Между установкой и запуском `mgr_tpl` лексиконные поля будут выводиться как голые ключи. Старые tpl с `{$field}` без `| lexicon` продолжат работать на старых данных (Fenom-теги в значениях) до пересборки.

Лексиконная ветка не затронута. Тесты `testGetThumbNonLexicon*LeavesInputAsExpression`, `testSetPlaceholdersPictureWithSlashPathsLeavesInputAsExpression` подтверждают новое поведение.
