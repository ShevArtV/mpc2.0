1.0.0-alpha (в разработке)
==============
Визуальный фронт-редактор контента для проектов на migxpageconfigurator (mpc).
Зависит от mpc 2.4.0+. Ведётся поэтапно; в прод — после перехода на -rc.

- [M6] Скаффолд пакета:
  - bootstrap-плагин (OnWebPagePrerender) — инжектит overlay-UI на фронте, если у текущего mgr-пользователя есть permission `mpcve_edit` и edit-режим включён (query-параметр / cookie);
  - standalone connector `assets/components/mpcvisualeditor/connector.php` → роутер `Connector` (экшены — в M7);
  - фасад `Mpcve` (тонкий, делегирует в mpc для записи значений);
  - PSR-4 автозагрузчик `services/autoload.php` (+ переиспользует vendor mpc);
  - permission `mpcve_edit` (resolver), системные настройки `mpcve_*`;
  - overlay.css / mpcve.js — каркас (редакторы — M8).
- [M7, частично] Бэкенд save-путь для rfield/tv:
  - экшен коннектора `field/save` → `Handlers\FieldSaveHandler` → `Mpcve::writeField` → mpc `FieldWriter` (M4);
  - принимает address (JSON) + value, resourceId из адреса/запроса; типы rfield/tv сохраняются, type=field вернёт «not implemented» до M2;
  - фронт-редакторы, вызывающие `field/save` (TextEditor и пр.), — M8. RowSave/ImageUpload-хендлеры — далее.
- [M8, срез] Рабочее редактирование текста + диспетчер по типу поля:
  - тулбар доступен авторизованному ВСЕГДА (плагин inject-only, не подменяет контент); тумблер режима (cookie `mpcve_editing`) с перезагрузкой — тулбар не пропадает;
  - редактор диспатчится по ТИПУ поля: экшен `fields/types` (`FieldTypesHandler`) отдаёт карту `field→тип` из живого `mpc_base` (text/richtext/image/media/rows); text/richtext реализованы, image/media/rows — заглушки;
  - text-редактор inline (`contenteditable`, Enter/уход — коммит, Esc — отмена, выделение всего поля), аффорданс по типу (рамка/бейдж);
  - сохранение ПЕР-ПОЛЕВОЕ: коммит → `field/save` → `FieldWriter` (static→sbp/global, иначе ресурс; вложенные поля строк списка — `parentField`+`idx`). Whole-DOM `page/save` оказался деструктивным (рендер = склейка тип+ресурс + lazyload/fake-img) — отключён.
  - плагин `OnWebPagePrerender` переведён в inject-only: маркеры берутся из ШТАТНОГО рендера (mpc keep-markers), lazyload/expand-скрипты сохраняются; edit-mode больше не расходится с прод-рендером.
  - фикс прав на сохранение: убран ручной `session_start()` в коннекторе (ломал mgr-сессию на web-контексте при `session_handler_class=modSessionHandler`/БД) — `initialize('web')` поднимает ту же сессию.
- [M9, срез] Редактор изображений с загрузкой файла:
  - новый экшен коннектора `image/upload` → `Handlers\ImageUploadHandler`: валидация (белый список jpg/jpeg/png/gif/webp/svg/avif, `getimagesize`-MIME, лимит `mpcve_max_upload` ~10 МБ, `is_uploaded_file`), запись в тот же media source, что и грабер (`mpc_media_source` → `default_media_source`), папка `mpc_media_path` + `images/`, имя = санитайз + короткий sha1 контента (дедуп одинаковых, без коллизий) → возврат публичного URL;
  - фронт: `editors.image` — модалка с превью (из реального `src`, в edit-mode lazyload отрабатывает), drop-zone + выбор файла, превью нового через `FileReader`; на «Загрузить и сохранить» → `image/upload` → `field/save` (тот же адрес, что у текста) → обновление `src` без перезагрузки;
  - фоновые картинки: элемент с `data-mpc-field` и фоном в inline `style` (`background-image`/`background`) распознаётся как `image` (`bgUrl`/`hasBg`); превью и запись — в `style.backgroundImage` того же элемента (`currentImageSrc`/`setImageSrc`), сохранение пути — тем же `field/save`;
  - `api.upload` (multipart), стили модалки в overlay.css, лексиконы `mpcve_uploaded`/`mpcve_err_upload*`/`mpcve_err_source`;
  - тест `ImageUploadHandlerTest` (чистое ядро `processUpload`/`sanitizeFileName` с fake-source): запись, формат URL/имени, детерминизм, ошибка createObject.
- Зависимость: mpc **2.4.11+** (keep-markers в каттере для edit-mode, точечная запись полей).
- Ограничения (далее): редакторы media/rows; загрузка картинки требует у `<img>` data-mpc-адреса (есть у полей-картинок); поля 2-го уровня вложенности (`data-mpc-field-2`, список-в-списке — `ConfigFieldWriter` пишет один уровень); списки с `limit/offset` (возможный сдвиг `idx`).
