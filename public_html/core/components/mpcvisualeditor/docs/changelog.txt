1.0.0-alpha (в разработке)
==============
Визуальный фронт-редактор контента для проектов на migxpageconfigurator (mpc).
Зависит от mpc 2.4.0+ (для панели скрытых полей — 2.5.4+). Ведётся поэтапно; в прод — после перехода на -rc.

- [M16.1] Скрытые поля правятся ПО ТИПУ (как на странице). RTE-тулбар вынесен в общий `editors/rte.js` (`rteToolbarHtml`/`wireRteToolbar`) — используют и модальный richtext-редактор, и панель скрытых полей. В панели (`panels.js`) richtext теперь не голый contenteditable, а RTE с форматированием (тулбар над областью, `.mpcve-hpanel__rtebox`); textarea (тип отдаётся `FieldTypesHandler` отдельно с M16) — `<textarea>`; text — input; image — загрузка. Файлы: `editors/rte.js` (new), `editors/richtext.js` (использует общий), `panels.js`, `overlay.css`.
- [M16] Текст: инлайн только для простого text; textarea и richtext — в МОДАЛКЕ. Раньше и text, и richtext правились инлайново (contenteditable), многострочный textarea тоже шёл как text. Теперь: (1) `text` — инлайн contenteditable (как было, простые однострочные); (2) `textarea` — модалка с `<textarea>` (значение plain text, обновляем `el.textContent` без перезагрузки) — новый `editors/textarea.js`; (3) `richtext` — модалка с настоящим RTE: тулбар B/I/U/S, H2/H3/¶, маркир./нумер. списки, ссылка (с возвратом выделения после prompt), убрать ссылку, очистить формат — на нативном `document.execCommand` (без сборки/зависимостей); значение = innerHTML, пишется `field/save` (лексикон-round-trip как у инлайна) — новый `editors/richtext.js`. Детект типа: `FieldTypesHandler::editorType` теперь отдаёт `textarea` отдельно от `text`; `ftypeToEditor` (address.js) — `textarea`/`richtext`. Реестр `editors/index.js`: `richtext` больше НЕ роутится в инлайн-текст. Файлы: `editors/{textarea,richtext}.js` (new), `editors/index.js`, `address.js`, `constants.js` (TYPE_HINT), `overlay.css` (`.mpcve-ta__*`/`.mpcve-rte__*`), `FieldTypesHandler.php`. RTE на execCommand — v1; при необходимости позже заменить на полноценный редактор.
- [M15.3] Аудио: кнопка-аффорданс «✎» для открытия редактора. M15.2 (force controls) сделал `<audio>` видимым, но клик по нему всё равно не открывал редактор: `<audio controls>` целиком занят НАТИВНЫМ контрол-баром — UA обрабатывает клик внутри (play/seek) и НЕ шлёт `click` на host-элемент, поэтому `bindClicks` не срабатывал (у video есть кликабельный кадр над баром — потому video работал). Теперь `attachAudioBadges` (app.js) оборачивает каждый `audio.mpcve-editable` в `.mpcve-audio-wrap` и вешает кнопку `.mpcve-media-badge` (✎) → клик открывает `editors.media`. `removeAudioBadges` разворачивает при выходе. CSS — `overlay.css`. force-controls (M15.2) оставлен как гарантия видимости (если секцию перережут с `controls=0` → условный рендер не выведет атрибут). Обёртка `inline-block` со shrink-to-fit схлопывала аудио с темовым `width:100%` до мин-ширины (бар превращался в огрызок) — JS замеряет ширину аудио ДО оборачивания и задаёт её обёртке (`> audio { width:100% }`), вид сохраняется.
- [M15.2] Фиксы по тестированию video/audio: (1) `<audio>` без `controls` имеет нулевую видимую область (0×0) → по нему нельзя кликнуть, чтобы открыть редактор (видео всегда видно — кадр/постер). В режиме правки `markEl` временно включает нативные `controls` на audio (`data-mpcve-controls`-флаг), `unmarkEditable` снимает их при выходе. (2) Сайтовый `expand.js` (`getImgData`) падал `Cannot read properties of undefined (removeAttribute)`, если контент по data-lazy/src — не SVG (битый путь/растр/медиа): добавлен null-guard `if (!svg) return`. Файлы: `mark.js`, `app.js`, `migxpageconfigurator/js/web/expand.js`.
- [M15.1] Булевы атрибуты video/audio стали редактируемыми (чекбоксы controls/autoplay/loop/muted) — после того как каттер начал рендерить их УСЛОВНО (mpc 2.5.22-rc: `renderBoolAttrs` → `{if $rec.controls}controls{/if}`, `0` реально выключает). - [M10] Скрытые поля У БЛОКА (config-driven). Поля, вырезанные из страницы (`data-mpc-remove`) или вспомогательные (напр. `resources`), DOM-маркера не имеют — инлайн-редактором их не достать. При входе в edit-mode фронт грузит `mpc_config` (новый экшн `config/get` → `Mpcve::readConfig` → `FieldWriter::readConfig`, resource+global уровни одним запросом) и вешает кнопку «⊕ N» в углу КАЖДОГО блока, у которого есть скрытые поля: на секции (`data-mpc-section`) — её скрытые top-поля, на элементе списка (`data-mpc-item`, level-1) — скрытые под-поля именно этой строки. Клик → модальная панель этого блока: для каждого поля input/textarea + Сохранить (запись прежним `field/save`, адрес с `parentField`/`idx` для строк). Что показываем: для СЕКЦИИ — поля вкладки «Стили секции» `inline_styles`/`class_names` (кнопка «Стили», фиксированный набор, заполняется из конфига или пусто — чтобы задать ещё не существующее; `css_file_path` исключён; диф конфиг−DOM для секций не годится — контент идёт через rfield/tv, в конфиге только служебные ключи). Для СТРОКИ списка (`data-mpc-item`, level-1, кнопка «⊕ N») — скрытые скалярные под-поля строки (конфиг минус структурные/DOM-маркеры). Подписи полей — caption из конфигуратора (`fields/types` отдаёт `labels`), не ключи; для известных — ручные («Inline-стили»/«CSS-классы»). v1: правка скаляров (text/textarea/richtext); медиа-записи (img/video/audio/picture) и вложенные записи пропускаются (правятся на странице) — value-based редактор записей отложен. Якорь кнопки: блок временно получает `position:relative`, если был `static` (откат при выходе). Диагностика в консоль (`[mpcVE] скрытые поля: …`). Файлы: `ConfigGetHandler`, `Connector` (+экшн), `Mpcve::readConfig`, `mpcve.js` (+триггеры/панель), `overlay.css` (+стили). Заменяет промежуточный вариант с одной кнопкой в тулбаре.

- [медиа, шаг 1: img-запись] Редактор картинок стал ЗАПИСЬ-aware для migx-поля `img`: раньше фронт слал голый URL и `ConfigFieldWriter` затирал им всю запись `[{src,alt,title,width,height}]` (теряя alt/title/размеры). Теперь для `<img>` (не фон, `ftype!=bg_img`) модалка даёт править `alt`/`title` (предзаполнены из атрибутов) + заменить файл; на сохранении собирается полная запись `[{MIGX_id:1,src,alt,title,width,height}]` (width/height — из натуральных размеров загруженной или из текущих) и пишется как `value` (бэкенд хранит как есть — правок не требует). Можно сохранять и без нового файла (только атрибуты). DOM обновляется (src/alt/title). Фон/`bg_img` — прежний путь-режим. Лексиконы (alt/title в лексикон-форме) — следующий шаг (пишем через `LexiconManager`, не литералом). Дальше по шагам: video/audio, picture.
