1.0.0-alpha (в разработке)
==============
Визуальный фронт-редактор контента для проектов на migxpageconfigurator (mpc).
Зависит от mpc 2.4.0+ (для панели скрытых полей — 2.5.4+). Ведётся поэтапно; в прод — после перехода на -rc.

- [M11.1] Вложенные списки + медиа-списки. (1) Фикс: поля ВЛОЖЕННЫХ списков (level-2+, `data-mpc-field-2` в `data-mpc-item-1`) не сохранялись — `fieldAddress` строил один уровень и с багом item-attr (`data-mpc-item-N` вместо `N-1`), запись уходила в top-level поле. Теперь `buildRowPath` собирает ПОЛНЫЙ путь `[{field,idx},…]` (фикс attr-маппинга), бэкенд пишет по пути (`ConfigFieldWriter` 2.5.13). (2) Медиа-списки (`list_images`/`list_pictures`/…): редактор строк раньше писал «нет рядов» (искал `data-mpc-item` внутри `<img>`). Теперь `listRows` детектит медиа-список — ряды = повторяющиеся одноимённые соседи (img/picture/video/audio); превью по alt/src. add/delete/move работают. Правка отдельной картинки медиа-списка (whole-row) — отдельным шагом.
- [M11] Редактор строк списка (add/delete/move). Клик по контейнеру списка (`data-mpc-field` с `data-mpc-item` внутри, тип `rows`) → панель строк: каждая строка с превью текста + кнопки ↑/↓/✕, внизу «+ Добавить строку». Операция → новый экшн `row/op` → `Mpcve::rowOp` → `FieldWriter::writeRowOp` → `ConfigFieldWriter` (add/delete/move в mpc_config). После операции — перезагрузка страницы (список перерисовывается из конфига). Значения строк (вкл. лексикон-ключи) едут со строкой → переводы целы при перестановке/удалении; новые строки — пустые (лексиконизируются на нарезке с `1`). v1: списки уровня 1 (вложенные — по полям, как раньше). Файлы: `RowOpHandler` (+экшн `row/op` в Connector), `Mpcve::rowOp`, `mpcve.js` (`openRowsEditor`/`listAddress`), `overlay.css` (`.mpcve-rows`). Заглушка `rows` заменена рабочим редактором.
- [M10.1] Фикс: стили секции правятся на ПРАВИЛЬНОМ уровне (каскад). Стилевые поля (`inline_styles`/`class_names`) — каскад-поля mpc: на рендере РЕСУРС-уровень перекрывает global (`Render::applyResourceCascade`). Панель «Стили» для static-секции писала в global, и правка маскировалась ресурсным переопределением → «не обновляется после перезагрузки». Теперь стилевые поля читаются/пишутся на уровне РЕСУРСА (текущая страница), если секция есть в ресурс-конфиге; иначе — global (его и берёт каскад без переопределения). `mpcve.js`: `findSectionInLevel(name, level)`, `sectionStyleHidden` — resource-first. Контент/строки (`sectionConfig`) по-прежнему static→global.
- [M10] Скрытые поля У БЛОКА (config-driven). Поля, вырезанные из страницы (`data-mpc-remove`) или вспомогательные (напр. `resources`), DOM-маркера не имеют — инлайн-редактором их не достать. При входе в edit-mode фронт грузит `mpc_config` (новый экшн `config/get` → `Mpcve::readConfig` → `FieldWriter::readConfig`, resource+global уровни одним запросом) и вешает кнопку «⊕ N» в углу КАЖДОГО блока, у которого есть скрытые поля: на секции (`data-mpc-section`) — её скрытые top-поля, на элементе списка (`data-mpc-item`, level-1) — скрытые под-поля именно этой строки. Клик → модальная панель этого блока: для каждого поля input/textarea + Сохранить (запись прежним `field/save`, адрес с `parentField`/`idx` для строк). Что показываем: для СЕКЦИИ — поля вкладки «Стили секции» `inline_styles`/`class_names` (кнопка «Стили», фиксированный набор, заполняется из конфига или пусто — чтобы задать ещё не существующее; `css_file_path` исключён; диф конфиг−DOM для секций не годится — контент идёт через rfield/tv, в конфиге только служебные ключи). Для СТРОКИ списка (`data-mpc-item`, level-1, кнопка «⊕ N») — скрытые скалярные под-поля строки (конфиг минус структурные/DOM-маркеры). Подписи полей — caption из конфигуратора (`fields/types` отдаёт `labels`), не ключи; для известных — ручные («Inline-стили»/«CSS-классы»). v1: правка скаляров (text/textarea/richtext); медиа-записи (img/video/audio/picture) и вложенные записи пропускаются (правятся на странице) — value-based редактор записей отложен. Якорь кнопки: блок временно получает `position:relative`, если был `static` (откат при выходе). Диагностика в консоль (`[mpcVE] скрытые поля: …`). Файлы: `ConfigGetHandler`, `Connector` (+экшн), `Mpcve::readConfig`, `mpcve.js` (+триггеры/панель), `overlay.css` (+стили). Заменяет промежуточный вариант с одной кнопкой в тулбаре.

- [M6] Скаффолд пакета:
  - bootstrap-плагин (OnWebPagePrerender) — инжектит overlay-UI на фронте, если у текущего mgr-пользователя есть permission `mpcve_edit` и edit-режим включён (query-параметр / cookie);
  - standalone connector `assets/components/mpcvisualeditor/connector.php` → роутер `Connector` (экшены — в M7);
  - фасад `Mpcve` (тонкий, делегирует в mpc для записи значений);
  - PSR-4 автозагрузчик `services/autoload.php` (+ переиспользует vendor mpc);
  - permission `mpcve_edit` (resolver), системные настройки `mpcve_*`;
  - overlay.css / mpcve.js — каркас (редакторы — M8).
- [M7, частично] Бэкенд save-путь для rfield/tv:
  - экшен коннектора `field/save` → `Handlers\FieldSaveHandler` → `Mpcve::writeField` → mpc `FieldWriter` (M4);
  - принимает address (JSON) + value, resourceId из адреса/запроса; типы rfield/tv сохраняются, type=field вернёт «not implemented» до M2;
  - фронт-редакторы, вызывающие `field/save` (TextEditor и пр.), — M8. RowSave/ImageUpload-хендлеры — далее.
- [M8, срез] Рабочее редактирование текста + диспетчер по типу поля:
  - тулбар доступен авторизованному ВСЕГДА (плагин inject-only, не подменяет контент); тумблер режима (cookie `mpcve_editing`) с перезагрузкой — тулбар не пропадает;
  - редактор диспатчится по ТИПУ поля: экшен `fields/types` (`FieldTypesHandler`) отдаёт карту `field→тип` из живого `mpc_base` (text/richtext/image/media/rows); text/richtext реализованы, image/media/rows — заглушки;
  - text-редактор inline (`contenteditable`, Enter/уход — коммит, Esc — отмена, выделение всего поля), аффорданс по типу (рамка/бейдж);
  - сохранение ПЕР-ПОЛЕВОЕ: коммит → `field/save` → `FieldWriter` (static→sbp/global, иначе ресурс; вложенные поля строк списка — `parentField`+`idx`). Whole-DOM `page/save` оказался деструктивным (рендер = склейка тип+ресурс + lazyload/fake-img) — отключён.
  - плагин `OnWebPagePrerender` переведён в inject-only: маркеры берутся из ШТАТНОГО рендера (mpc keep-markers), lazyload/expand-скрипты сохраняются; edit-mode больше не расходится с прод-рендером.
  - фикс прав на сохранение: убран ручной `session_start()` в коннекторе (ломал mgr-сессию на web-контексте при `session_handler_class=modSessionHandler`/БД) — `initialize('web')` поднимает ту же сессию.
- [M9, срез] Редактор изображений с загрузкой файла:
  - новый экшен коннектора `image/upload` → `Handlers\ImageUploadHandler`: валидация (белый список jpg/jpeg/png/gif/webp/svg/avif, `getimagesize`-MIME, лимит `mpcve_max_upload` ~10 МБ, `is_uploaded_file`), запись в тот же media source, что и грабер (`mpc_media_source` → `default_media_source`), папка `mpc_media_path` + `images/`, имя = санитайз + короткий sha1 контента (дедуп одинаковых, без коллизий) → возврат публичного URL;
  - фронт: `editors.image` — модалка с превью (из реального `src`, в edit-mode lazyload отрабатывает), drop-zone + выбор файла, превью нового через `FileReader`; на «Загрузить и сохранить» → `image/upload` → `field/save` (тот же адрес, что у текста) → обновление `src` без перезагрузки;
  - фоновые картинки: элемент с `data-mpc-field` и фоном в inline `style` (`background-image`/`background`) распознаётся как `image` (`bgUrl`/`hasBg`); превью и запись — в `style.backgroundImage` того же элемента (`currentImageSrc`/`setImageSrc`), сохранение пути — тем же `field/save`;
  - `api.upload` (multipart), стили модалки в overlay.css, лексиконы `mpcve_uploaded`/`mpcve_err_upload*`/`mpcve_err_source`;
  - тест `ImageUploadHandlerTest` (чистое ядро `processUpload`/`sanitizeFileName` с fake-source): запись, формат URL/имени, детерминизм, ошибка createObject.
- [медиа, шаг 1: img-запись] Редактор картинок стал ЗАПИСЬ-aware для migx-поля `img`: раньше фронт слал голый URL и `ConfigFieldWriter` затирал им всю запись `[{src,alt,title,width,height}]` (теряя alt/title/размеры). Теперь для `<img>` (не фон, `ftype!=bg_img`) модалка даёт править `alt`/`title` (предзаполнены из атрибутов) + заменить файл; на сохранении собирается полная запись `[{MIGX_id:1,src,alt,title,width,height}]` (width/height — из натуральных размеров загруженной или из текущих) и пишется как `value` (бэкенд хранит как есть — правок не требует). Можно сохранять и без нового файла (только атрибуты). DOM обновляется (src/alt/title). Фон/`bg_img` — прежний путь-режим. Лексиконы (alt/title в лексикон-форме) — следующий шаг (пишем через `LexiconManager`, не литералом). Дальше по шагам: video/audio, picture.
- [кросс-ресурс] `fieldAddress` читает обёртку `data-mpc-res="<id>"` (`el.closest('[data-mpc-res]')`) → `address.resourceId` = тот ресурс, а не текущая страница. Для редактирования полей ресурса, выводимого сниппетом в ДРУГОМ ресурсе (превью/аннотация статьи в листинге). Бэкенд (mpc 2.5.1) пишет в тот ресурс/его лексикон. Требует mpc с поддержкой `data-mpc-res`.
- [тип по ftype] Под фичу mpc 2.5.0 «произвольные имена полей»: тип редактора теперь берётся из атрибута `data-mpc-ftype` на элементе (в edit-mode маркеры сохраняются) — это точнее карты `fields/types` из `mpc_base`, т.к. реальные поля называются произвольно. `editorTypeFor`: `ftypeToEditor` (richtext→richtext, img/picture/bg_img→image, video/audio→media, list*→rows, text/textarea/number/checkbox→text); структурный список без ftype (`[data-mpc-item]`) → rows. Иначе — прежняя детекция (карта/тег/фон). Чинит потерю форматирования richtext-полей с произвольными именами (раньше детектились как text → innerText при сохранении). Требует mpc **2.5.0+**.
- Ограничения (далее): редакторы media/rows; загрузка картинки требует у `<img>` data-mpc-адреса (есть у полей-картинок); поля 2-го уровня вложенности (`data-mpc-field-2`, список-в-списке — `ConfigFieldWriter` пишет один уровень); списки с `limit/offset` (возможный сдвиг `idx`).
