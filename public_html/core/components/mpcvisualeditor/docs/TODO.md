## Сделано (для контекста)
- Произвольные имена полей секции (ftype/fcap/fdesc), динамические списки `mpc_auto_*`, прототипы типов в `mpc_base` — mpc 2.5.0.
- Редактор `img` (загрузка файла, alt/title, фоновые картинки), тип редактора по `data-mpc-ftype`.
- Лексикон-aware запись (текст/медиа-под-поля), лексиконизация полей ресурса (`rfield` → `mpc_resource_<field>`), кросс-ресурс `data-mpc-res` — mpc 2.5.1.
- Единый exclude для всех полей: `rfield` теперь проходит через `excludeLexiconFields` (грабер `ResourceFieldGrabber::lexiconize` + каттер `replaceResourceMarkers`, публичный `LexiconManager::isExcluded`); `pagetitle` в дефолтном списке (читается MODX напрямую → в колонке остаётся значение, не ключ). Другие нативные поля (`menutitle`/`longtitle`/…) — добавлять в project-specific exclude-файл при необходимости.
- Лексиконизация TV (`data-mpc-tv`) по аналогии с rfield: грабер пишет TV-значение=ключ + текст в лексикон, каттер рендерит `{'mpc_resource_tv_<name>' | lexicon}`, `FieldWriter::writeTv` правит лексикон-ключ. Отдельный неймспейс `mpc_resource_tv_` (не коллизит с rfield того же имени). Exclude и degradation (нет ключа / лексиконы off → прямой TV) — как у rfield. mpcVE-сторона (роутинг `type:'tv'` → writeTv) уже была — редактирование TV из фронта теперь лексикон-aware. mpc 2.5.3.
- Скрытые поля у блока (v1): кнопка «⊕ N» в углу секции / элемента списка → панель этого блока, config-driven. mpc 2.5.4 (`FieldWriter::readConfig`) + mpcVE M10 (`config/get`, `Mpcve::readConfig`, `ConfigGetHandler`, триггеры/панель в `mpcve.js`/`overlay.css`). Скалярные поля секции + скрытые под-поля строк списков (level-1), которых нет в DOM; запись прежним `field/save`. Медиа/записи пока пропускаются.
